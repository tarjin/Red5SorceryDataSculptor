For composers, not just programmers

A score you can read as a spreadsheet.

Each sounding note is a row. You can edit the music in a familiar spreadsheet, ask an LLM to develop ideas, or compose entirely on your own. At export time, calculations are regenerated with code and the resulting files can be independently checked.

No packaged standalone SymphonyCSV exporter exists yet. The current general export workflow uses an LLM with file and code tools.

01 / The composition grid

Music written the way you count it.

Instead of beginning with MIDI ticks, begin with a measure, a spoken count, a pitch and a duration. This excerpt comes from the Bach Prelude in C example at 60 beats per minute.

This is a readable selection of columns. The downloadable CSV retains all 85 columns, including calculated timing, MIDI and notation settings, source information and optional lyrics.

Human-readable timing

Count with words such as “One and” or “Two la”. Six meters are defined in the experimental manual, including 6/8 and 7/8.

Running time

See approximately where each note begins in minutes and seconds. MIDI ticks remain the precision authority; display time is calculated.

Room to grow

Optional columns cover lyrics, articulation, voices, controllers and provenance. Some of these remain outside current exporter coverage.

02 / The workflow

The composer decides. Code calculates.

SymphonyCSV is intended for human composers working with LLMs. The LLM can suggest, explain and help export; it does not become the authority over your musical choices.

  1. Write

    Enter notes, measures, spoken counts, durations, tempo, meter and instruments in a CSV file. No live keyboard performance is required.

  2. Explore

    Make as many revisions as you like. Ask an LLM for ideas, or edit the sheet yourself. A working draft need not recalculate after every tiny change.

  3. Prepare

    Before an export, validate the full file and regenerate dependent fields using deterministic code wherever possible. Keep the previous version and record overwrites.

  4. Export and check

    Create a Standard MIDI File or MusicXML document, then parse and compare the note events. Keep a receipt of what passed, changed or could not be verified.

The agreement: The composer decides. Code calculates. The LLM assists and explains. Exports are verified. These are documented workflow rules, not a promise that an LLM can never make a mistake.

  • MIDI

    Export from the 85-column Bach master was reconstructed and verified note by note. The manual documents the comparison and limitations.

  • MusicXML

    CSV-to-MusicXML export has been demonstrated. Comprehensive validation of MusicXML export from the complete 85-column format remains future work.

  • Six meters

    2/4, 3/4, 4/4, 5/4, 6/8 and 7/8 have documented count vocabularies. The v0.3.2 manual reports synthetic MIDI round-trip tests; broader real-music and notation-software tests are pending.

  • Original music

    Glass Bells is an original four-measure study composed by Spock using SymphonyCSV. T produced it in MuseScore Studio 4 using a soft-strings sound and shared its score with the announcement of Red5Sorcery Studios.

05 / What comes next

An experiment worth sharing.

SymphonyCSV is not a released V1 specification or a packaged application. The format is intended to be openly documented after further testing and review. No public software licence has yet been selected.

For now, we are learning by composing, exporting, listening and checking. If you enjoy thinking in notes, measures and patterns, the manual and Bach example are an invitation to experiment.
